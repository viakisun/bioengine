## 2. Fix scope (commit 158b670)

[src/plant/skin/StemFamilyTubeNetworkBuilder.ts](src/plant/skin/StemFamilyTubeNetworkBuilder.ts):

3개 변경 (모두 한 함수 + 헬퍼 내부 — biological model 영향 없음):

### 2.1 petiole embed clamp
```ts
// 기존
const embedDepth = Math.max(parentRadius * embedFrac, embedFloor);  // petiole: max(parentR×0.6, 1.5mm)

// 신규 (petiole-only 분기)
if (edge.type === 'petiole') {
  embedDepth = Math.min(Math.max(parentRadius * 0.25, 0.0005), 0.0020);
}
```
이유: D99 parentR=7.7mm일 때 기존 embed 4.6mm → child가 stem 안쪽 4.6mm
부터 시작 → parent skin에 가려져 emerge 지점이 stem에서 떨어져 보임.

### 2.2 petiole radialDir = PlantBase azimuth
```ts
// 기존: averageTangent(bonePath, 3)으로 derive
const sourceDir = averageTangent(edge.bonePath, ...);

// 신규: petiole은 PlantBase azimuth 사용
const sourceDir = edge.type === 'petiole'
  ? vsub(childGraphStart, parentCenter)  // PlantBase azimuth
  : averageTangent(...);                  // 다른 type은 기존 유지
```
이유: drooping/curving D99 petiole의 첫 3 bone tangent 평균이 trunk 방향으로
휘어 radialDir이 ~157° 뒤집힘 → parentSurfacePoint가 stem 반대편 (audit
[v0.13-iter19-phaseA-gate-fail.md] — deleted but documented here).

### 2.3 computeParentInfo: bone 보간
```ts
// 기존: nearest bone endpoint (p0 or p1) snap
let bestEndpoint: 0 | 1 = 1;
... if (d0 < bestDistSq) { ... bestEndpoint = 0; }

// 신규: bone segment에 projection
const t = clamp((childStartPos - p0) · (p1 - p0) / segLenSq, 0, 1);
const centerlinePoint = lerp(p0, p1, t);
const radius = lerp(swollenBone.r0, swollenBone.r1, t);
```
이유: 굵은 D99 stem bone segment(>5mm)에서 petiole이 중간에 attach하면
endpoint snap이 최대 4mm Y 오프셋 — Phase A+radialDir 적용 후 잔존하던
n16 outlier(4.47mm gr→rd, V-dominated 4.14mm)의 원인.

이 세 변경의 combined effect로 D99 worst 13.29mm → 1.23mm 달성 (Phase A
clamp만으로는 13.29mm, +radialDir로 4.47mm, +interpolation으로 1.23mm).

**Verdict**:
- raw metric (parentSurfacePoint vs childGraphStart > 1mm)은 **고도로
  inflated**: D45 raw=41이지만 실제 시각 disconnect (vsRenderedRoot)는 0.
- petiole이 raw에 포함되는 이유: runtime parentSurfacePoint 계산 결과가
  PlantBase petiole start와 1mm 이상 차이날 수 있으나, 이는 metric 정의
  자체의 over-sensitivity. embed clamp 적용 후 실제 rendered root는 가까움.
- breakdown: rachis/pedicel/peduncle도 다수 포함 — 이들 모두 false
  positive 가능성. 실제 disconnect 측정 metric은 vsRenderedRoot (Phase D
  결과 0/1).
- **Iter 20 권장**: `floatingCandidateCount` metric을 `vsRenderedRoot` 기반
  으로 재정의. 단순히 metric만 바꾸면 AC1_NO_FLOATING_FRAGMENT가 자연
  PASS.
