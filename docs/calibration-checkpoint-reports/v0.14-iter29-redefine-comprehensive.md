## Executive summary

Iter 29 v3.3 refactored the **tomato growth digital twin core architecture**.
PlantBase now owns _all_ growth state computation (thermal time, phyllochron,
phytomer, organ states, source-sink proxy). Skeleton merely references the
PhytomerNode and exposes spatial transforms. Skin is data-driven —
no growth-function calls.

**89 invariants** (59 new + 30 prior) pass across 7 Phases (Phase 0 → 6).

adds 10 more invariants → **86 + 10 = 96 pass target** at Quality Gate D).

## Future work — DEFORMATION-FUTURE-01

`LeafPostureState.curl` is currently a posture parameter. Semantically it's
a **deformation** (chlorophyll/turgor loss in senescence + drought) rather
than a rigid-body posture component. A future `LeafDeformationState`
type would carry:

- `curl: number` (0..1)
- `wilting: number` (0..1) — turgor loss
- `creaseDepth: number` (mature leaf vein deflection)
- `damageSiteSeed: number` (insect/disease patches)

Phase 7 candidate (post-Iter 29) — currently retained on
`LeafPostureState` to keep Skin geometry signal flow compact.

## Conclusion

Iter 29 v3.3 establishes the **PlantBase → Skeleton → Skin responsibility
separation** that the codebase had been incrementally drifting toward
across Iter 18–28. Skin is now strict data-driven: a leaf's mesh is
fully determined by `PhytomerNode.leaf` + `OrganAnchor` + `visualGenome`.
A future "skin-only mode" toggle that runs Skin against a stubbed
PhytomerNode tree (for visual showcase / testing) becomes trivial.

The calibration pack opens the door to **measurement-driven validation**:
any out-of-band `leaf.targetAreaCm2` at a given `ageTT` checkpoint emits
a structured `CalibrationWarning` that names the node, organ, parameter,
and source — a debugging primitive that did not exist before Iter 29.
