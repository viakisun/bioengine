## 4. Phase 2 — Organ Visibility Lifecycle 통합 (commit 4fc249c)

**원칙**: 한 organ을 부분만 렌더하지 않음. graph petiole edge ↔ leaf blade mesh 같은
lifecycle 공유.

도입 ([buildTomatoSkeletonGraph.ts](src/plant/skeleton/buildTomatoSkeletonGraph.ts)):
```ts
export const LEAF_VISIBILITY_THRESHOLD = 0.05;

export function isLeafOrganVisible(leaf): boolean {
  return leaf.visibility.visible && leaf.sizeFactor >= LEAF_VISIBILITY_THRESHOLD;
}

export function isTrussOrganVisible<T extends {...}>(truss: T): truss is TrussWithCurves<T> {
  if (!truss.visibility.visible) return false;
  if (!truss.peduncleCurve || !truss.rachisCurve || !truss.floralSites) return false;
  if (truss.peduncleCurve.length < 2) return false;
  return true;
}
```

적용 대상:
- `buildTomatoSkeletonGraph.addLeavesForAxis`: petiole edge 생성 조건 = `isLeafOrganVisible`
- `buildTomatoSkeletonGraph.addTrussesForAxis`: peduncle/rachis/pedicel edge 생성 조건 = `isTrussOrganVisible` (type guard로 narrowing)
- `SkinMeshPlant` leaf rendering loop: 동일 predicate
- `SkinMeshPlant` truss organ loop: 동일 predicate

→ Acceptance criteria #4 충족: "petiole, midrib, leaflet rib, leaf blade는 동일한 organ
visibility lifecycle을 공유"

## 5. Phase 3 — Junction Stitching (commit b3711cb)

**문제** (Phase 1.1 측정): 140/151 child edges가 parent surface로부터 > 1mm 떨어져 있어
"꽂혀 있는 듯" 인상. 기존 stitching:
```ts
embedDepth = parentRadius * embedDepthFrac[type]  // 0.6 ~ 0.8
```
parent radius < 2mm면 embed < 1.2mm로 충분히 박히지 않음.

도입 ([StemFamilyTubeNetworkBuilder.ts](src/plant/skin/StemFamilyTubeNetworkBuilder.ts)):
```ts
const DEFAULT_EMBED_DEPTH_FLOOR_M: Record<SkeletonEdgeType, number> = {
  mainStem:  0,
  sideShoot: 0.004,   // 4mm
  petiole:   0.0015,  // 1.5mm
  peduncle:  0.0020,  // 2mm
  rachis:    0.0010,  // 1mm
  pedicel:   0.0010,  // 1mm
};

embedDepth = Math.max(parentRadius * embedFrac, FLOOR_M[type]);
```

[SkinMeshPlant.ts](src/twin/SkinMeshPlant.ts):
```ts
buildPlantSkinMesh(..., { parentSwellingScale: 1.25 });  // 1.10 → 1.25
```

→ Thin parent (petiole) 에서도 child가 absolute 1-4mm 깊이로 embed되어 root bone이 충분한
transition cone 형성. junction 부근 parent radius 25% swelling으로 visual 용접 강화.

Acceptance criteria #5: "main stem - petiole, main stem - truss, rachis - pedicel
junction은 시각적으로 접합되어 보여야 한다" — Phase 4 floor와 결합으로 충족.

## 6. Phase 4 — biological vs render Radius 분리 (commit 10b3687)

**원칙** (사용자 #4 review 직접 인용):
> "줄기와 잎의 생장이라는게, 그것도 과학적인 생육 모델링으로 구현된 데이터를 바탕으로
> 해야지. 땜빵처럼 하고 잇는거 아니지?"

engine biological radius = 모델 정확성, render radius = pixel visibility. 두 값 분리.

도입:
```ts
const RENDER_RADIUS_FLOOR_M = 0.0008;  // 0.8mm
```

preprocessBonePathsWithSwelling 안에서 swollen bone (이미 edge.bonePath clone)에 floor
적용. **edge.bonePath (graph engine value) 변경 없음**:
```ts
bone.r0 = Math.max(bone.r0, RENDER_RADIUS_FLOOR_M);
bone.r1 = Math.max(bone.r1, RENDER_RADIUS_FLOOR_M);
```

emitEdgeRecursive의 rootBone도 floor 적용.

### 검증 — D45 showcase, before vs after Phase 4
| edge type | biological min | render min (before Phase 4) | render min (after Phase 4) |
|---|---:|---:|---:|
| mainStem | 10.7mm | 10.7mm | 10.7mm (floor 미적용) |
| **petiole** | **0.24mm** | **0.28mm** ❌ sub-pixel | **0.92mm** ✅ |
| peduncle | 2.5mm | 2.88mm | 2.88mm |
| rachis | 1.3mm | 1.70mm | 1.70mm |
| pedicel | 1.4mm | 1.77mm | 1.77mm |

→ petiole 0.92mm로 모든 화면에서 visible. biological 0.24mm는 변하지 않음 → calibration
모델 무영향. debug overlay (`__skinplantStats`)에서 두 값 둘 다 확인 가능.
