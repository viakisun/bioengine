## 7. 핵심 발견 — H4 negative + 진단 (Section 8b reject Case A 매핑)

### Case A 정확히 매칭 (Section 8b)
```text
신호: unused 감소 (작음) + fruit_redistributed > 0 (작음) BUT cohort/visible/abortion 변화 없음
진단: redistribution path가 fruit growth/survival에 연결되지 않음
   = step-wise stepCap이 너무 tight해서 surplus 받을 capacity 부족
```

### 추가 진단 — stepCap saturation
```text
surplus 462g, redistribute capacity ≤ 0.4g (0.087%)
→ 모든 fruit이 자기 step별 Gompertz cap에 거의 도달
→ "다른 fruit이 받을 수 있는 양"이 거의 없음
→ surplus는 unused_pool에 그대로 남음

→ 진짜 lever는 source-sink redistribution이 아니라
   per-fruit cap layer 자체 (Iter 6e-3 후보)
```

### Layer 6 영구 진단 (산출물 #5 — Iter 6e + 6e-2 합산)
```text
Layer 6: Source-sink allocation
  - redistribute_to_vegetative: vegetative saturation으로 무효 (Iter 6e)
  - fruit_priority_limited: per-fruit stepCap saturation으로 무효 (Iter 6e-2)
  → Layer 6 redistribute 정책 자체가 reproductive 부족 해결 도구 아님 (영구 확정)
  → 진짜 lever는 (a) cap layer 자체 (Iter 6e-3 stepCap 완화)
```
