## 3. Case B 원인 — embed depth의 시각 부작용

### 현재 코드 ([StemFamilyTubeNetworkBuilder.ts:520-525](src/plant/skin/StemFamilyTubeNetworkBuilder.ts#L520-L525)):
```ts
const embedFrac = embedDepthFrac[edge.type] ?? 0.6;       // petiole=0.6
const embedFloor = DEFAULT_EMBED_DEPTH_FLOOR_M[edge.type] ?? 0;  // petiole=0.0015
const embedDepth = Math.max(parentRadius * embedFrac, embedFloor);
const parentSurfacePoint = vadd(parentCenter, vscale(radialDir, parentRadius));
const childStart = vsub(parentSurfacePoint, vscale(radialDir, embedDepth));
```

D99 mainStem radius 7.7mm (median 6.19mm는 surface→child 거리). embedDepth =
max(7.7×0.6, 1.5) = 4.6mm. parentSurface는 swelling 1.25 적용 후 outward.
즉 child mesh root는 parent surface로부터 4.6mm 안쪽에서 시작.

**의도**: child mesh가 parent skin 안으로 박혀 들어가 junction이 자연스럽게
weld됨. 이론적으로 정확.

**부작용** (사용자가 본 disconnect의 진짜 원인 추정):
1. child mesh root는 parent 안쪽 (4.6mm)
2. child mesh가 parent surface 밖으로 emerge하기까지 거리 4.6mm 동안 parent
   skin에 가려져 보이지 않음
3. parent skin이 child mesh를 완전히 덮어버리고, child가 parent 밖으로
   삐져나오는 시점부터 visible
4. 시각적으로는 "petiole이 stem mesh에서 약간 떨어진 점에서 갑자기 emerge"

D99에서 mainStem radius가 D45 대비 약 1.5배 → embedDepth도 1.5배 → 부작용도
1.5배 더 명확. user가 "잎이 떠 있어 보임"이라 한 게 이 양상과 일치.

## 4. 추정 시각 모델

```
D99 mainStem radius:    7.7mm
swelling scale:         × 1.25 → parent skin surface @ 9.6mm from center
embed depth (petiole):  max(7.7 × 0.6, 1.5) = 4.6mm
graph petiole start:    @ 7.7mm from center  (= PlantBase stem surface)
rendered child root:    @ 9.6mm - 4.6mm = 5.0mm from center  (안쪽)
parent skin outer:      @ 9.6mm from center  (swelling 후)

→ rendered child mesh가 5.0mm~9.6mm 구간을 통과하는 동안 parent skin에 가려짐
→ 9.6mm 밖으로 나가야만 시각적으로 child가 보임
→ 그 사이 4.6mm 만큼 "stem과 petiole 사이 비어 보이는" 구간 발생
```

D45는 stem radius 3.85mm → 4.6mm 정도 → 약간 더 미세하나 동일 현상.


→ 가려짐 0. 다만 micro-gap 발생 가능.

## 6. 부차 발견 — `floatingCandidateCount=41`은 절반 false positive

Iter 18A SSOT #176의 `floatingCandidateCount`는 "child bonePath[0].p0 vs
parentSurfacePoint 거리 > 1mm"를 카운트. 본 audit으로 확정:
- `bonePath[0].p0` = PlantBase root (정확한 stem surface)
- `parentSurfacePoint` = `parentCenter + radialDir * parentRadius` (런타임 계산,
  swelling 적용 안 됨 — pre-swell)
- 둘 거리는 거의 0이어야 함

그런데 41건이 floating. 가능 원인:
- `radialDir` 계산이 azimuth와 미세 차이 (childDir projection로 인한)
- 또는 parentRadius 계산이 bone 내부 보간점에서 추출 (정확한 node radius와 다름)

**Iter 19 또는 별도 cleanup PR**에서 floatingCandidateCount의 정의 reconsider.
현재는 시각 disconnect의 직접적 indicator가 아님 — `gr→rd` (graphRenderedDelta)
가 더 정확한 disconnect metric.
